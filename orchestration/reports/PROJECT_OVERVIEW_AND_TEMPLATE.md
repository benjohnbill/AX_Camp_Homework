# 프로젝트 전체 기획서

### 1) 기획 의도

본 프로젝트는 사용자가 자신의 기록을 통한 서사 구축을 목표로 한다. 서사는 story와 다르다. 서사는 나만의 맥락과 이야기, 삶 그 자체이다. 나의 저 먼 과거와 현재, 미래를 연결하는 방향성을 가진 것이 서사이다. 너무나 복잡해지고, 다양한 환경에 압도되어 살아가는 현대인들은 정보에 휩쓸리기 마련이다. 이해하기보다는, 존중하고 넘어가는 것이 상책이 되었다. 그러나, 자신을 바라보는 것에서도 많은 사람들이 그러한 관점을 갖고 살아간다. 스스로를 돌아보기 보다, 외부의 스토리에 눈을 돌린다. 허나, 자기서사는 자신의 삶을 결정해야만 하는 순간 뿐 아니라, 스스로에 대한 연결성을 부여함에 따라, 의미를 생산한다. Narrative Loop 프로젝트는, 사람들이 글쓰기 라는 수단을 통해 사용자의 짧은 단상(핸드폰 OCR) 혹은 긴 호흡의 에세이 등을 매일 스스로와 연결해 나가도록 함을 목적으로 한다.

핵심 사용자 루프는 다음과 같다.

1. 기록 작성(Write)
2. 저장 확인(Save)
3. 하루 단위 재오픈/재조회(Re-open/Re-query)
4. 회고 경험 및 연결(Universe)

cf) Chronos 기능을 통한 타이머(포모도로 스타일) 활용 서사, Desk 기능을 통한 직접적인 사용자의 글쓰기(Obsidian 스타일), 

### 2) 구현/분석 방법

구현은 역할 분리 아키텍처를 기준으로 진행했다.

	본 프로젝트의 구현 방법은 단순 기능 개발이 아니라, CT(Control Tower)-Worker의 Agnet 팀 체계를 중심으로
  설계되었다. 각각은 Codex CLI(CT/BE, Antigravity(FE), Android Studio(AND)로 이루어졌다. CT는 사이클 목표와 판정 기준을 정의하고, Worker는 역할별 실행과 증적 수집을 담당한다. 역
  할은 Backend(인증 계약/상태코드 검증), Frontend(UI 서사 카피 및 오류 복구 UX), Android Studio(실기기·
  에뮬레이터 사용자 여정 검증)로 분리했으며, 각 결과는 독립적으로 제출되되 최종 판정은 CT가 통합한다.

  실행은 문서와 JSON 계약을 하나의 파이프라인으로 연결하는 방식으로 운영했다. 먼저 orchestration/
  task.json에서 사이클 기준 과업과 수용 조건을 고정하고, orchestration/dispatch/*.worker-prompts.json으
  로 워커별 지시를 분기한다. 이후 각 워커는 orchestration/results/*.result.json에 실행 로그와 증적을 남
  기며, CT는 이를 기반으로 orchestration/handoff/*.handoff.json을 갱신해 accept/blocked를 결정한다. 이
  과정에서 trace_id, task_id, schema-valid 여부를 일치시키는 것을 기본 규칙으로 삼아, “작동해 보이는 상
  태”가 아니라 “검증 가능한 상태”를 유지했다.

	프로젝트의 핵심 로직은 데이터 처리 정확성과 사용자 체감 흐름을 동시에 확보하는 방식으로 설계했다. 검
  색은 키워드 기반 매칭과 임베딩 유사도 검색을 결합한 하이브리드 구조에 OpenAI API 기반 재구성 단계를
  더해, 재조회 품질과 문맥 일관성을 높였다. 한글 입력은 정규화/패치 규칙을 별도로 두어 OCR 오인식과 띄
  어쓰기 변형에 대한 복원력을 확보했고, 저장은 사용자 즉시 피드백이 필요한 경로는 동기 처리, 후속 정리·
  확장 처리는 비동기 처리로 분리했다. 동기/비동기의 구분은 분량과 로딩시간(UX)을 바탕으로 구분하였다. 데이터 계층은 Supabase를 기준으로 기록 생성-조회-회고 흐름을 고정했으며, Android OCR 입력은 인증 게이트웨이를 거쳐 Backend 저장/검색 파이프라인으로 연결되도록 구성했다. Streamlit의 Stream, Desk, Chronos 등 5개 기능 구획은 이 로직을 사용자 여정에 맞춰 노출하는 인터페이스 계층으로 설계하여, 루프외에 사용자가 지속적으로 웹앱을 사용하며, 자신의 데이터베이스와 함께 성장하는 느낌을 일관되게 체감하도록 했다.

### 3) 기능 및 유저 시나리오

1. 외부 텍스트 해석형 OCR 시나리오

  - 사진 속 텍스트/책과 그것에 대한 필기를 OCR로 처리. 이를 통해 "사용자의 감상을" 입력
  - 핵심 가치: 외부 정보와 자신의 의견을 “내 서사”로 재해석해 저장
  - 결과물: 원문(OCR) + 내 감상(텍스트) + 연결 태그

  2. 자기 필기 보존형 OCR 시나리오

  - 내 손글씨 OCR + DB 아카이브
  - 핵심 가치: "아날로그 글쓰기" 습관을 디지털 서사 자산으로 전환
  - 결과물: 손글씨 원본 이미지 + 인식 텍스트 + 정정본 + 타임스탬프

  3. Universe 탐색형 시나리오

  - Universe 모드 내 대시보드/3D 뷰(Render 활용)에서 기록 흐름 탐색
  - 핵심 가치: 축적된 기록의 관계를 회고하고 의미를 발견
  - 결과물: 시계열/토픽/감정축 기반 탐색, 재조회 진입점 제공

### 4) 한계 및 고도화 방안

기술적 한계 (Current Technical Limitations)
   * Android WebView 의존성: 유니버스(분석) 모드가 WebView 기반(Universe3DFragment.kt)으로 구현되어
     있어, 오프라인 상태에서의 분석 기능 제약 및 네이티브 대비 미세한 반응 속도 지연(Latency) 리스크가
     존재함.
   * 관계형 중심 데이터 구조의 확장성: 현재 Supabase(Postgres) + pgvector + SQLite fallback이 공존하는
     구조이나, 데이터가 기하급수적으로 늘어날 경우를 대비한 전문 그래프 DB나 전용 벡터 인프라 도입 전
     단계임.
   * 서사 통찰 연결의 초기 단계: RRF(Reciprocal Rank Fusion) 하이브리드 검색은 구현되었으나, 장기적으로
     축적된 기록에서 "삶의 맥락적 통찰"을 자동으로 추출하여 연결해 주는 고차원 로직은 아직 초입 단계임.
	 ex> [AI가 스스로 수천 개의 로그를 훑으며 "당신은 지난 3년간 2월만 되면 번아웃이 오는데, 그 원인은 주로 타인과의 관계 설정 원칙을 어기고, 그 과정에서 술을 자주 먹었기 때문이군요"라고 스스로 결론을 내리고 제안하는 단계]
   * OCR 노이즈 및 교정 UI: 비전 API를 통한 추출 과정에서 발생하는 오인식(특히 복잡한 필기체)을
     사용자가 앱 내에서 정교하게 교정하고 피드백하는 UI/UX가 보완되어야 함.


  3. 단계별 고도화 방안 (Roadmap)


  [단기: Phase 1 - 안정화 및 네이티브 강화]
   * CameraX 전용 UI 도입: 시스템 인텐트 의존도를 낮추고 앱 내 전용 카메라 UI를 통해 OCR 스캔 품질
     최적화.
   * 모바일 로컬 캐싱: 주요 서사 데이터를 Room/SQLite에 캐싱하여 통신 음영 지역에서도 타이머 및 쓰기
     기능의 연속성 보장.


  [중기: Phase 2 - 지능형 서사 에이전트]
   * 능동적 서사 개입(Intervention): RAG(검색 증강 생성) 성능을 고도화하여 사용자의 현재 결정과 과거
     원칙이 충돌할 때 AI가 실시간으로 성찰을 제안.
   * 관계 시각화 입체화: 단순 리스트를 넘어 서사 간의 상관관계를 보여주는 지식 그래프(Knowledge Graph)
     시각화 도입.


  [장기: Phase 3 - 소셜 확장 및 집단 지성 (거버넌스 전제)]
   * 선택적 서사 공유 (SNS): 프라이버시가 보장된 범위 내에서 "자신의 별자리"를 타인과 공유하고 영감을
     주고받는 소셜 네트워크 확장. 타인과 직접적인 연결이 될 수도 있고, 데이터적 활용에 한정일 수도 있음.
   * 협업형 AI 피드백: 사용자 동의 및 비식별 설계 완료를 전제로, 유사한 고민을 가진 다른 사용자의 서사
     데이터를 참고하여 AI가 더 넓은 범위의 결정을 돕는 기능 검토.
