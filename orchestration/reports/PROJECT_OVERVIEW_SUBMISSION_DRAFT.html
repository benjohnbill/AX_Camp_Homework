1) 기획 의도

본 프로젝트는 단순한 생산성 도구가 아니라, 사용자가 자신의 기록을 통해 삶의 맥락을 연결하고 자기결정을 강화하도록 돕는 "자기서사 시스템" 구축을 목표로 한다. 여기서 서사는 소비되는 외부 이야기(story)가 아니라, 개인의 과거-현재-미래를 잇는 내적 방향성과 의미 생성의 구조를 뜻한다.

정보 과잉과 빠른 전환이 일상화된 환경에서 많은 사용자는 자신의 경험을 깊게 이해하기보다 흘려보내기 쉽다. Narrative Loop는 이 단절을 줄이기 위해, 모바일 OCR 기반의 짧은 단상부터 긴 호흡의 에세이까지 글쓰기 행위를 하나의 연속된 루프로 연결한다.

MVP의 기준은 기능 개수의 확장이 아니라, 사용자가 반복적으로 신뢰할 수 있는 경험 루프를 유지하는 데 있다.

  • 기록 작성(Write)
  • 저장 확인(Save)
  • 재오픈/재조회(Re-open/Re-query)
  • 회고 경험(Universe)

인증/세션 변동 상황에서도 루프가 끊기지 않아야 하며, 실패 상황(401/403)에서도 사용자가 다음 행동을 선택할 수 있어야 한다. 운영 의사결정은 CT의 계약/증적 기반 판정 원칙을 따른다. 이 기획 의도는 이후 구현/분석 방법, 기능 및 유저 시나리오, 한계 및 고도화 방안으로 구체화된다.

2) 구현/분석 방법

  • 역할 분리 아키텍처: Android / Gateway-Auth / Streamlit / Core Logic-DB
  • Contract-first 인증: 401/403 코드 분기와 Bearer->Cookie 전이 규칙 명시
  • Narrative-first UX: 기본 UI 카피와 기술 payload(디버그) 분리
  • 시나리오 기반 검증: 사용자 여정 단위로 증적 수집
  • CT 판정 방식: result/handoff JSON + strict gate + runtime evidence 결합

3) 기능 및 유저 시나리오 / 분석 결과 및 인사이트

상태 표기: PASS / PARTIAL / BLOCKED

시나리오 1. 기록 작성/저장 PARTIAL

  • 가치: 첫 의사결정을 시스템에 남기는 시작점
  • 인사이트: 저장 성공 피드백의 명확성이 재사용률에 직접 영향
  • 증적: Android 최종 런타임 증적 추가 수집 필요

시나리오 2. 재오픈/재조회 PARTIAL

  • 가치: 저장 신뢰 형성의 핵심 구간
  • 인사이트: 재조회 성공은 기능 신뢰뿐 아니라 심리적 안정감에 기여
  • 증적: 에뮬레이터/실기기 공통 재확인 필요

시나리오 3. Universe 진입/렌더링 PARTIAL

  • 가치: 기록-회고 루프 완성
  • 인사이트: 시각 효과보다 인증 경로 일관성이 이탈 방지에 중요
  • 증적: mobile path 증적 보강 필요

시나리오 4. 401/403 UX PASS

  • 가치: 실패 상황에서 복구 행동 유도
  • 인사이트: 기술 용어를 줄이고 경계/재연결 중심 카피를 제공하면 실패 체감이 감소
  • 증적: frontend cycle3 result + backend 계약 상태코드 증적

시나리오 5. Lifecycle 안정성 PARTIAL

  • 가치: 모바일 실사용성 확보
  • 인사이트: 세션/뷰 상태 복원성이 체감 품질에 직접 영향
  • 증적: Android runtime 재검증 필요

4) 한계 및 고도화 방안

한계

  • Android 빌드/실행 환경 의존성으로 검증 루프 중단 위험 존재
  • 일부 증적 수집 수동 처리로 반복 비용과 편차가 큼
  • OCR/Retrieval 확장 경로의 운영 정합성은 추가 보강 필요
  • OneDrive/경로/로컬 Python 변동성으로 검증 재현성이 흔들릴 수 있음

고도화 방안

  • Android CI에 Gradle health check + 핵심 여정 계측 테스트 도입
  • status+code -> UX 카피 매핑 표준을 공용 모듈/테스트로 고정
  • CT 자동판정 파이프라인(Probe + Gate + Scenario Matrix + Schema Validation) 강화
  • RRF/Retrieval 지표를 주기 리포트로 운영 KPI에 연결
