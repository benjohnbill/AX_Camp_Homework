# DEBUG_TOKEN_GOVERNANCE.md

## 1. 목적
이 문서는 Narrative_Loop의 디버그 JWT 토큰 운영 규칙을 정의한다.
핵심 목표는 다음 3가지다.

1. 발행/소비 주체와 책임 경계를 명확히 한다.
2. 유출/오용 위험을 줄인다.
3. 폐기/재발급 절차를 표준화한다.

---

## 2. 범위
- 포함: Staging/개발 환경의 디버그 토큰 운영
- 제외: 프로덕션 사용자 인증 체계 전체 설계

프로덕션 환경에서는 디버그 토큰 발급을 금지한다.

---

## 3. 주체 정의

- 발행 주체(Issuer): Antigravity Backend
- 소비 주체(Consumer): Android 앱(DEBUG 빌드), WebView 최초 요청
- 정책 관리자(Owner): 프로젝트 오너(사용자)
- 검토/정합성 가이드: Codex CLI

---

## 4. 역할과 책임 (RACI)

| 항목 | Antigravity | Android Studio | 프로젝트 오너 |
|---|---|---|---|
| 디버그 토큰 발급 엔드포인트 구현 | R | C | A |
| JWT 서명키 보관/회전 | R | I | A |
| 토큰 앱 주입 방식(TokenStore/DEBUG UI) | C | R | A |
| 토큰 하드코딩 방지 점검 | C | R | A |
| 유출 사고 대응(폐기/재발급 지시) | R | C | A |
| 운영 기록 보관 | R | I | A |

R=Responsible, A=Accountable, C=Consulted, I=Informed

---

## 5. 발급 정책

### 5.1 발급 원칙
1. 디버그 토큰은 Staging/개발에서만 발급한다.
2. 서버에서만 발급한다(클라이언트 자체 발급 금지).
3. 짧은 수명(권장 30~120분, 기본 60분)을 사용한다.
4. 최소 클레임만 포함한다.

### 5.2 권장 클레임
- `iss` (예: `ax-camp-staging`)
- `aud` (예: `android-universe`)
- `user_id`
- `sub`
- `iat`
- `exp`
- `jti` (권장: 개별 토큰 추적용)

### 5.3 권장 발급 인터페이스
- 내부 보호 엔드포인트 예시: `POST /debug/token`
- 입력: `user_id`, `aud`, `ttl_minutes`
- 출력: 단기 JWT

---

## 6. 소비 정책

1. Android는 DEBUG UI를 통해 토큰을 주입한다.
2. 토큰을 소스코드/Gradle/git tracked 파일에 하드코딩하지 않는다.
3. 최초 요청은 `Authorization: Bearer <JWT>`로 전송한다.
4. 서버가 세션 쿠키를 발급하면 이후 요청은 쿠키 인증을 우선 사용한다.
5. 만료/401/403 발생 시 사용자에게 재로그인/토큰 갱신 안내를 노출한다.

---

## 7. 금지사항

1. 채팅/문서/스크린샷에 전체 토큰 원문 공유 금지
2. `?token=...` URL 파라미터 방식 사용 금지(예외: 폐쇄 테스트 한정, 기본 금지)
3. 프로덕션 배포물에 DEBUG 토큰 주입 UI 포함 금지
4. 토큰을 crash log/analytics payload에 기록 금지

---

## 8. 폐기/재발급 규칙

### 8.1 정기 회전
- 서명키 정기 회전(권장 월 1회 이상)

### 8.2 즉시 폐기 트리거
- 토큰이 채팅/문서/이슈 트래커에 노출된 경우
- 토큰 오용 의심(비정상 IP/과도한 요청)
- 팀원 기기 분실/유출 의심

### 8.3 즉시 폐기 절차
1. Antigravity가 서명키를 회전한다.
2. 기존 토큰 전체를 무효화한다.
3. 새 디버그 토큰을 재발급한다.
4. Android DEBUG UI에서 기존 토큰 삭제 후 신규 토큰 입력한다.
5. `401/403` 경로와 정상 경로를 재검증한다.

---

## 9. 운영 로그/감사

서버 로그에는 아래만 남긴다.
- 발급 시각
- 발급 대상 `user_id`
- `aud`
- 만료 시각
- `jti` 또는 토큰 해시(원문 금지)

토큰 원문 전체는 로그에 남기지 않는다.

## 10. 체크리스트

### 발급 전
- [ ] 환경이 staging/development 인가?
- [ ] TTL이 단기(<=120분)인가?
- [ ] 클레임(`iss`, `aud`, `user_id`, `exp`)이 맞는가?

### 앱 주입 전
- [ ] DEBUG 빌드인가?
- [ ] 토큰 하드코딩이 없는가?
- [ ] 기존 만료 토큰을 제거했는가?

### 검증
- [ ] 토큰 유효 시 Universe 페이지 로드 성공
- [ ] 토큰 무효/만료 시 401/403 처리 + 안내 메시지
- [ ] 탭 전환/백그라운드 복귀 시 안정 동작

## 11. 표준 요청 문구 (복붙용)

### Antigravity에 재발급 요청
```
디버그 토큰 재발급 요청:
- environment: staging
- aud: android-universe
- user_id: debug_user_001
- ttl_minutes: 60
또한 기존 디버그 토큰은 즉시 폐기(무효화)해주세요.
```

### Android 팀 적용 요청
```
새 디버그 JWT를 DEBUG UI로 주입하고 기존 토큰을 삭제한 뒤,
Universe(3D) 탭에서 인증/401/403/복귀 동작까지 스모크 테스트를 수행해주세요.
```
